## 命令面 (v1)

```text
sweep-nm                    预览: 清单 + 体积 + 合计, 零副作用
sweep-nm --yes              执行删除
sweep-nm --force            连同疑似安装树一并删除 (默认跳过)
sweep-nm --exclude <名字>   临时追加排除, 可重复
sweep-nm --include <名字>   只清理命中名单的目录, 可重复
sweep-nm --config <路径>    指定配置文件 (优先于 SWEEP_NM_CONFIG)
sweep-nm config             查看实际生效的配置: 来源 + 路径 + 文件状态
sweep-nm init               初始化向导: 交互式生成配置文件
sweep-nm --help             帮助
sweep-nm -h                 --help 的别名
```

- `--force` 只放行「疑似安装树」(判定与理由见 [删除安全闸](../../../../docs/designs/deletion-guard.md)「语义闸」): 缺省情形下这类目标不进删除批 (安装树删后无法由项目级重装恢复), 加旗标才照常纳入; 它不影响安全闸的不变量, 也不改变预览的零副作用语义。
- 仓库名 `sweep-node-modules`; npm 包名 `@iyowei/sweep-node-modules`; 命令名取短变体 `sweep-nm` (仿 `flatten-folder-cli` → `flatten-folder` 的旧例, 包名与命令名由此解耦)。
- **主命令 + 子命令形态**: 缺省 `sweep-nm` 即清理流程 (预览; 加 `--yes` 执行); 子命令 `init` 承载初始化向导, `config` 报告本次实际生效的配置。子命令位只为工具自身的辅助动作保留, 不承载其他清理能力 (模拟器等另立兄弟项目)。
- **`config` 子命令与 `--config` 旗标形近义反**: 前者报告「实际用的是哪个」(来源 + 路径 + 文件状态, 退出码恒 0, 文件不存在属报告内容而非错误), 后者指定「用哪个」; 二者在帮助页命令面里相邻列出。与帮助里「默认配置位置」的分工: 那行刻意屏蔽环境变量、只答平台默认 (见 CLI 包 `src/help.ts` 的 `defaultConfigPath`), 只对没做任何覆盖的用户成立, 故帮助里同处点明其限定并指向 `sweep-nm config` 查实际生效路径。
- 判定模型与执行模型见 [ADR 0002](../../../sweep-node-modules/docs/adrs/0002-fixed-config-and-preview-execution.md); 初始化向导的交互见 [配置与初始化](../../../../docs/designs/config-and-initialization.md)。

## 退出码

| 码  | 含义                                                                                           |
| --- | ---------------------------------------------------------------------------------------------- |
| 0   | 成功 (含预览、空结果)                                                                          |
| 1   | 任一失败 (删除失败 / 整批中止 / 未处理目标 / 配置损坏或不存在 / 参数错误 / 无配置下的执行拒绝) |

## 输出规格 (视觉规范: 紧凑式 + 色块)

设计语言: 少线多色块、紧凑排版, 零依赖手写 ANSI。各输出面共用同一套构件: 顶栏 (`▍` 起首、整行反色加粗, SGR `1;7`)、中性行 (`░` 起首、缩进 2 + 整行压暗, SGR `2`)、成功 `✓` (绿, SGR `32`)、失败 `✗` (红, SGR `31`)、强调 (加粗, SGR `1`); 着色开关由 `cli.ts` 按 TTY 与 `NO_COLOR` 统一判定后传入各面, 降级契约各面同款 (见下方「降级」)。下面按面登记: 清单 / `config` 子命令 / `init` 向导 (`--help` 页只取顶栏一形 `▍ SWEEP-NM  <动作自述>`, 其余为对齐的命令列, 不另立规格)。

### 清单 (预览 / 执行)

```text
▍ SWEEP-NM  预览 · 2 个根: ~/dev · ~/lab · bun 1.4.2
  ░ 排除生效: legacy-demo (2 处)
  █ 4.6 GB  acme-web         ~/dev/acme-web
  ▓ 366 MB  data-pipeline    ~/dev/data-pipeline
  ▒  86 MB  docs-site        ~/lab/docs-site
  █ 合计 3 处 · 5 GB   加 --yes 执行删除
```

- 顶栏: 反色色块 + 模式 (预览 / 执行) + 根数 + 运行时自述; 根数 ≤ 3 时直接列出根路径 (家目录缩写); 运行时自述形如 `bun 1.4.2` (取运行时自报字段, 直接跑与经启动器跑都报真身), 仅真终端展示 (非 TTY 不增噪音);
- 顶栏下方的中性提示行 (`░`, 仅真终端): 名单回执等本次运行的说明; 走 stdout, 与清单共用视觉语言, 不打断顶栏与清单的紧邻关系 (名单写错的告警仍走 stderr 并保持在顶栏之前, 位置本身即是强调);
- 清单按体积降序; 每行: 体积档位色块 (大 ≥ 512 MiB / 中 ≥ 100 MiB / 小) + 右对齐体积 + 项目名 (亮) + 路径 (暗, 剥 `node_modules` 后缀并按显示宽度对齐, CJK 双宽);
- 疑似安装树行 (判定见 [删除安全闸](../../../../docs/designs/deletion-guard.md)「语义闸」): 路径保留 `/node_modules` 后缀 (剥掉后缀后剩下的目录会被读成项目, 后缀是唯一的类别线索), 行尾标注判定理由 `疑似安装树: <理由>`; 存在被跳过项时, 在合计 / 汇总行之后补一行中性说明 (`疑似安装树 N 处默认跳过 (加 --force 一并清理)`): 它是安全事实, 非 TTY 下同样出现, 不属 TTY 专属面;
- 跨设备行 (判定与解除路径见 [删除安全闸](../../../../docs/designs/deletion-guard.md)「设备边界」): 路径照常剥 `/node_modules` 后缀, 行尾按形态标注 (`跨设备: 根与目标之间有挂载点` / `跨设备: 目标本体即挂载点`); 执行模式行尾说明为 `已跳过 (把该挂载点声明为独立根即可清理)` / `已跳过 (挂载点无法删除, 需先卸载该卷)` (与普通删除失败区分: 它从未进入删除批); 存在被跳过项时, 按形态各补一行末行说明 (`跨设备目标 N 处默认跳过 (<该形态的解除路径>)`), 只在出现该形态时出, 与疑似安装树行同属非 TTY 下同样出现的安全事实;
- 测不到体积的目标保留在清单中作**占位行** (`?` + 中性色块 + 行尾注「体积统计失败: <原因>」), 不计入合计; 执行时计入失败;
- 名字含控制字符 / 需折叠空白时, 显示名经净化并在行尾标注「名字已净化显示」; 净化是全输出面 (清单 / stderr 诊断 / `config` 报告 / 向导的路径回显行 / `--help` 的默认配置位置行) 共用的唯一实现, 语义与覆盖面见 [行为契约](../../../../docs/protocol/behavior-contract.md) OF-14;
- 末行合计色块 (处数 + 总量), 预览模式附 `--yes` 提示;
- 执行模式: 逐行结果色块 (`✓` / `✗` + 失败原因; 疑似安装树被跳过时行尾注「已跳过 (加 `--force` 一并清理)」, 与普通删除失败区分: 它从未进入删除批), 汇总行含**释放体积** (`汇总 成功 N 处 · 释放 X · 失败 M 处`); 整批中止时逐行标注「整批中止, 未执行删除」并给出理由与未执行处数;
- 错误与告警走 stderr (TTY 下带红色 `✗` 前缀), 不污染 stdout 清单流; 其文本与清单显示名同一源净化 (控制字节与换行注入既不得直达终端, 也不得随 tee / CI 落盘、日后回放再生效), 行首缩进等自带排版保留: 诊断面承载的是最脏的数据 (磁盘路径 / `du` 的 stderr 原文 / 名单拼写 / 参数原文), 且 `--yes` 下 stdout 为空, 本面是删除前唯一可见信息, 故与清单面同等设防 (净化语义与覆盖面见 [行为契约](../../../../docs/protocol/behavior-contract.md) OF-14)。

### 体积档位与阈值

档位是绝对阈值 (按真实工作区分布重标, 不做分位数动态计算):

| 档位 | 阈值      | 色块     |
| ---- | --------- | -------- |
| 大   | ≥ 512 MiB | `█` (红) |
| 中   | ≥ 100 MiB | `▓` (黄) |
| 小   | < 100 MiB | `▒` (青) |

重标依据 (2026-09-24 实测, 主样本 n=5 加 2 项范围外观测): 原 1 GiB 阈值高于全样本最大值 (590.72 MiB; 范围外最大 622.26 MiB), 该档永不触发; 一维 k-means 的自然断点落在中 / 大之间 (约 405 MiB), 取更保守的 512 MiB, 令红块保持「稀有而醒目」。样本量小, 该组阈值属可再重标者 (不是一次定死的分位规则)。

### `config` 子命令 (TTY 着色版)

```text
▍ SWEEP-NM  配置 · 来源: --config 指定
  ░ 配置路径: /Users/iyowei/tmp/cli-review.json
  ░ 文件状态: 存在
```

- 顶栏复用同一 `▍` 前缀与反色加粗, 但其后只放本命令的动作名与核心信息段 (`配置 · 来源: <标签>`), 不承载清单顶栏的模式 / 根数 / 运行时自述 (config 不扫描, 无这些信息);
- 来源三档标签 (`--config 指定` / `环境变量 SWEEP_NM_CONFIG` / `平台默认`)、路径与文件状态口径、退出码语义 (恒 0) 见「命令面」的 `config` 条与 [行为契约](../../../../docs/protocol/behavior-contract.md) BC-35; 本条只管呈现形态;
- 路径与文件状态两行: 缩进 2 + 中性块 `░` + 压暗; 路径照实报告实际生效路径, 不做家目录缩写 (报告面「如实」优先于缩写可读性);
- 降级 (非 TTY / `NO_COLOR`): 仅去色码, `▍` 与 `░` 字符保留, 行结构与信息与着色版逐字等价 (与清单同款);
- 着色版属 TTY 专属面 (黑盒语料只覆盖降级形态), 登记见 [行为契约](../../../../docs/protocol/behavior-contract.md)「TTY 专属输出面」注。

### `init` 向导 (TTY 专属面)

```text
▍ SWEEP-NM  初始化向导
  ░ 首次使用, 先确定扫描范围
  扫描根 (逗号或空白分隔多个) [默认: ~]
  排除名单 (目录名) [回车采用默认名单 (20 条)]
  包含名单 (目录名, 可留空) [回车跳过]
  ░ 将写入 1 个扫描根 · 排除 20 条 · 包含 0 条
  确认写入? (Y/n)
  配置已写入: ~/.config/sweep-node-modules/config.json  ✓

  { 回显落盘 JSON 全文 (内容与文件一致, 整体缩进 2) }

  ░ 运行 sweep-nm 查看预览
```

- 向导顶栏只有 `▍ SWEEP-NM  初始化向导`, 不承载清单顶栏的模式 / 根数 / 运行时自述 (向导尚未扫描, 无这些信息); 这是「顶栏」在本规范中的一处显式例外, 不是规格漏项;
- 提问行保持 readline 原生形态 (`<问题> [<提示>]` 与 `<问题> (Y/n)`), 整行缩进 2 与叙述行同左缘 (全流程无缩进横跳); 提示段 (「[默认: ~]」/「[回车采用默认名单 (N 条)]」/「[回车跳过]」/「(Y/n)」) 压暗 (N 由内置默认名单长度实时派生, 排除一问空答即取该名单); 默认根经家目录缩写;
- 说明行 (导语 / `将写入 N 个扫描根 · 排除 M 条` / 运行提示) 走中性块 `░` + 压暗; 「将写入」行的 N / M / K 由解析结果实时计数 (不写死), 由 JSON 形态改为人话 (落盘 JSON 全文的回显仍在其后保留, 内容与文件一致、整体缩进 2);
- 校验失败行 (重问前的 `根不存在: <path>` / `根锚点链上有符号链接: <link> (根: <root>); 删除侧要求真实路径, …`, 同一根只给一条提示; 另有落盘前锚点检查的 `配置路径锚点链上有符号链接: <link> (配置: <path>); 写入会跟随符号链接改写其目标, …`, 它重问的是「确认写入?」这一问) 走红色 `✗` + 行首; 落盘成功行 (`配置已写入: <path>`) 把绿色 `✓` 置于**行尾** (整行以陈述收束, 勾号作句末确认符), 路径经家目录缩写;
- 覆盖确认与取消 / 拒绝分支沿用既有文案 (`配置已存在 (<path>), 是否覆盖? (y/N)` 与「已取消, 未写入配置」), 不新造视觉: 取消分支不加色块前缀, 免生误导语义;
- 向导是 TTY 专属面: 整条交互路径只在真终端存在 (入口即要求 TTY, 见 BC-29), 着色形态不产生语料条目 (登记见 [行为契约](../../../../docs/protocol/behavior-contract.md)「TTY 专属输出面」注与 [覆盖表](../../../../docs/protocol/conformance/coverage.md)「未覆盖条款」)。

### 降级

- 非 TTY / `NO_COLOR` / 终端能力不足 → 纯文本 (空格对齐, 零 ANSI), 着色与行结构不丢失: 清单与 `config` 面的 `▍` / `░` / 档位块字符保留, 仅去 SGR 色码;
- 按设计仅真终端出现的内容 (清单顶栏的运行时自述与名单回执、`config` 的着色版、`init` 向导整条交互路径) 不在此列, 非 TTY 不降级出现 (见 [ADR 0007](../../../sweep-node-modules/docs/adrs/0007-platform-portability.md))。

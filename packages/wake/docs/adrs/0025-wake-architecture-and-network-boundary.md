# ADR 0025: `wake` 子网感知广播、SSH 中继故障转移与无 shell 安全边界

- **状态**: 已采纳
- **日期**: 2026-11-27
- **所属包**: [`@iyowei/wake`](../../README.md) (仓库索引: [docs/adrs/README.md](../../../../docs/adrs/README.md))

## 背景

在多网卡与跨网段家庭/实验室运维拓扑中, 远程主机常同时连有 VPN 隧道网卡 (如 WireGuard `utun`/`wg`) 与多块物理网卡 (有线 + Wi-Fi), 且控制端 (笔记本) 可能位于外网或漫游在不同子网中。传统单行 `wakeonlan` 脚本存在三类工程痛点:

1. **虚拟网卡路由抢占**: 未绑定源 IPv4 的泛广播往往被默认路由送进 VPN 隧道接口而无法抵达目标主机所属二层广播域;
2. **跨网段无中继或单点失效**: 跨三层路由时 UDP 魔术包被路由器隔离, 需要经由局域网内多台常开跳板机 (如树莓派、常开工作站) 接力投递, 单一节点掉线时需要无缝切换备选中继;
3. **脚本拼接与凭据安全隐患**: 若直接经 SSH 执行自由字符串命令或盲信用户配置中的主机名/MAC, 极易在转发链路引入 `-oProxyCommand=` 选项注入或远端 shell 注入。

## 决策

1. **双路径协同与故障转移**:
   - 有中继列表 (`relays[]`) 且未传 `--local-only` 时, 按列表顺序调用远端中继节点上的 `wake --local-only --no-wait --force --json` (优先直传规范化 `--mac` 与 `--broadcast`, 使得中继节点无需本地预设 `config.json` 即可无状态发包; 无本地 MAC 且指定目标名时才委托中继按自身配置查找);
   - 当某中继 SSH 离线 (`255`)、超时或远端 `wake` 不可用时, 立即顺延尝试下一中继; 若全中继不可达且未传 `--no-local-fallback`, 自动退回本机直连局域网 UDP 广播。
2. **物理/虚拟网卡识别与同网段绑源发包**:
   - 通过 `listLocalLanInterfaces()` 识别并排后 VPN/容器虚拟接口前缀 (`utun` / `wg` / `tailscale` / `docker` / `veth` / `vmnet` 等);
   - 当配置了 `host` IPv4 且本机存在同子网物理接口时, 仅从该接口地址 `bind` 发送定向广播, 同时覆盖目标单播地址、子网广播与端口 `:9` / `:7`, 全程基于算术整除而非位运算完成子网运算以兼容静态约束。
3. **零 shell 注入的 SSH 调用协议**:
   - 中继进程通过 `execFile('ssh', ['--' ...], { shell: false })` 启动并锁定 `BatchMode=yes` 防挂起;
   - 所有转发向远端的数据 (`mac`、`host`、`port`、`broadcast`、`relay`、`target`) 必须经过正则与字符集双重白名单 (`TARGET_NAME_RE`、`BARE_HEX_RE`、`SAFE_REMOTE_TOKEN_RE`), 拒绝前导 `-` 与一切空白/控制符/元字符;
   - 配置文件使用 `wx` + `rename` 原子写入并在 POSIX 锁定 `0o600` 权限, 加载与保存前对父目录与目标路径执行 `lstat` 符号链接检查。

## 后果

- **正面**: 本机同网段、跨网段主中继、中继掉线自动转移至备选中继三种拓扑全由一套模型统一覆盖, 且中继侧只要求标准 `wake` 命令上线 (`PATH` 可达) 与免密 SSH 即可。
- **代价**: 跨网段中继场景依赖系统 `ssh` 客户端与密钥认证; 尚未内置独立守护进程或专用加密控制面。

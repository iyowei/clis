# 多维度极限压榨指南与 P0/P1/P2 双轨标定

调优野心要足够大: 优先追求改变复杂度、消除系统调用、零分配平铺内存与压榨运行时快路径的 **P0 / P1** 级跃迁; 同时把握辩证分寸, 不为了微小提升破坏代码可读性或搞全盘无意义重构。

## 1. 「入口严守、内核裸奔」的辩证原则

过度防御性编程是隐形性能杀手:

- **外层入口严守不变量**: 公开 API、CLI 参数入口、文件输入解析处集中做完空值检查、路径合法化、类型收窄与去重排序;
- **内部热循环信任不变量、极限压榨**: 一旦进入核心遍历或高频处理内循环, 去掉重复 `existsSync` / 冗余正则验证 / 防御性浅拷贝 (`[...arr]`) / 每步包一层 `try-catch` 与中间过渡对象。用静态类型与入口断言保障安全, 让热路径零额外税。

## 2. 探索维度与 I/O-CPU 分流准则

在 `prepare` 返回的 `profile` 中先看 `cpuRatio` 与 `userCpuShare` (`cpuUserMs / (cpuUserMs + cpuSysMs)`):

- **当 `profile.ioDominatedHint === true` (`cpuRatio < 0.20` 或 `userCpuShare < 0.30`)**: 瓶颈在系统调用 (`readdir`/`lstat`/子进程等待) 而非用户态 JS 计算。本轮优先攻 `arch` 与 `io` 维度, 禁止去微调局部语法。
- **当 `cpuRatio >= 0.20` 且 `userCpuShare >= 0.30`**: 用户态 JS 计算或内存分配占主导, 五大维度全面生效。

### 五维极限压榨焦点

1. **架构与算法 (`arch`, 首选 P0 来源)**:
   - 降维打击时间/空间复杂度 (如 $O(N^2)$ 扫描改扁平索引或前缀树);
   - 提前剪枝与零无效遍历 (在最廉价字符串/字节层面淘汰不可能命中的分支, 不等到 `stat`/`realpath`);
   - 批量化与流式流水线 (合并高频子进程或零散 syscall 为单次批量原语、无阻塞并发协作池或有界工作队列);
   - 借助 `--allow-cross-pkg` 打破 API 主包与 CLI 薄壳间冗余序列化/拷贝边界。
2. **I/O 与系统调用 (`io`)**:
   - 压榨内核往返次数 (优先带元数据的批量接口 `withFileTypes`, 按真实负载寻找最优并发拐点以填满队列但不挤爆内核调度);
   - 优先利用 [0006-dual-runtime-bun-first.md](../../../../docs/adrs/0006-dual-runtime-bun-first.md) 允许的 Bun 原生零拷贝 I/O (`Bun.file` / `Bun.spawn` / 原生快路径), 同时由 Node 回归守卫把住回退基线。
3. **具体实现与扁平内存 (`impl`)**:
   - 用字节切片/`charCodeAt` 状态机替换热循环里的正则捕获与 `split`/`trim` 中间字符串数组;
   - 用 `Uint8Array` / `Int32Array` 扁平缓冲或单遍索引扫描替代多层 `.map().filter().reduce()` 链;
   - 将高频动态正则与查找 `Set`/`Map` 提升至模块顶层静态初始化。
4. **GC 与零分配 (`gc`)**:
   - 对照 `profile.heapTopTypes` 中的 `string`、`Object`、`Array`、`Structure` 占比;
   - 热循环彻底追求 **Zero-Allocation**: 消除闭包捕获、临时选项对象 `{ ... }`、展开运算符与短命小数组;
   - 在安全边界内复用预分配缓冲 (`Buffer` / Scratch 数组), 避免高频触发新生代 Scavenge 与老生代晋升。
5. **解释器与 JIT (`interp`)**:
   - **兼顾 JSC (Bun DFG/FTL) 与 V8 (Node Maglev/TurboFan)**: 若某优化让 Bun 快但触发 `CROSS_RUNTIME_REGRESSION`, 立即看 `evaluate` 返回的 `nodeProfileHints` 排查 V8 去优化;
   - **保持绝对单态 (Monomorphic)**: 热点对象在构造函数/工厂字面量里按固定键顺序一次声明完毕, 绝不先建 `{}` 再动态挂载或 `delete` 属性;
   - 保持数组元素单一密集类型, 热函数参数类型严格一致以打通内联展开。

## 3. P0 / P1 / P2 事前预估与事后实测双轨标定

基准中的 `primary` (主路径) 用例参与加权净收益与峰值定向涨幅评估; `reference` (历史对照组) 只作参考与 `digest` 一致性校对, 不稀释主路径突破:

| 级别                       | 事前预估门槛 (AI 排优先级用)                                                     | 事后实测门槛 (`stats.ts` 基于 `primary` 自动定级)                                                              |
| :------------------------- | :------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------- |
| **P0 (架构/极限跃迁)**     | 算法换代、砍掉大量 syscall/子进程、重塑并发或零分配架构, 命中核心路径 $\ge 30\%$ | 主路径加权或显著核心用例耗时下降 **$\ge 25\%$** (或峰值 RSS 下降 **$\ge 40\%$**), 且无主路径或 Node 端劣化     |
| **P1 (实现/分配显著提效)** | 砍掉热循环分配、字节扫描替代高开销库调用、重整热点数据结构, 命中 $\ge 10\%$      | 主路径耗时下降 **$8\% \sim 25\%$** (或峰值 RSS 下降 **$20\% \sim 40\%$**) 且通过 Mann-Whitney U ($p \le 0.05$) |
| **P2 (局部微调)**          | 温路径细节优化、早退顺序微调、少量小对象消除                                     | 改善在噪声门槛之上 (**$2\% \sim 8\%$** 或 RSS 降 **$10\% \sim 20\%$**) 且统计显著                              |
| **无效回退 (`REVERT`)**    | 不适用                                                                           | 低于 **$2\%$**、未过显著性检验、任一主路径劣化、Node 副路径劣化超 **$3\%$** 或 `digest` 不一致                 |

# 优化效果的文档分层与体裁沉淀指南

当 `evaluate` 保留了一项优化并给出 `docActionRequired: true` (实测 `P0` 或 `P1`) 时, 须当场依据 [docs-layering.md](../../../../docs/designs/docs-layering.md) 与 [0019-two-tier-package-owned-docs.md](../../../../docs/adrs/0019-two-tier-package-owned-docs.md) 完成知识提炼与融合更新。

## 1. 归属位置与体裁裁决矩阵

| 实测级别与变更性质                               | 唯一允许的落盘位置                                                                                                                            | 体裁与融合要求                                                                                                                                                                           | 严禁做法                                                                                                                      |
| :----------------------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| **实验双队列与原始指标** (`accepted`/`rejected`) | `packages/<pkg>/bench/ledger/*.jsonl`                                                                                                         | 机器可读 JSONL 账本 (已由 `loop.ts` 自动维护)                                                                                                                                            | 严禁把试错流水账、失败清单或跑分原始 JSON 搬进 `docs/`                                                                        |
| **实测 `P2` 局部优化**                           | 目标包源码行内注释                                                                                                                            | 简明写清非显而易见的动机 (为何这样写更快/更省内存)                                                                                                                                       | 不污染任何 `docs/` 文件                                                                                                       |
| **实测 `P1` 实现/并发/内存策略**                 | **包级设计文档**: 主包 `packages/<product>/docs/designs/` 既有相关分册 (CLI 薄壳专属交互/渲染策略写入 `packages/<product>-cli/docs/designs/`) | **融合更新既有章节** (例: [scan-and-size.md](../../../../packages/sweep/docs/designs/scan-and-size.md) 的实现裁定与性能要点节), 补充实测前后对比、拐点参数与适用条件, 并登记「修订记录」 | 严禁每留一条优化就新建一篇碎片文档; 严禁在结尾机械追加 `## 补充说明`; 无独立 `docs/` 的小包 (如 `create-clis`) 不强建空壳目录 |
| **实测 `P0` 包内架构或契约决策**                 | **包级 ADR**: 主包 `packages/<product>/docs/adrs/NNNN-<slug>.md` (并更新该主包 `docs/README.md` 索引)                                         | 规范 ADR 四段式 (上下文 -> 放弃掉的方案 -> 决策与基准证据 -> 后果与代价); 编号须接**全仓当前最大四位 ADR 编号**顺延                                                                      | 严禁与仓级及其他包 ADR 重号; 严禁把无权衡取舍的小改动升格为 ADR                                                               |
| **跨多包的通用工程性能规范或方法论**             | **仓库级**: `docs/designs/` 或 `docs/adrs/NNNN-<slug>.md`                                                                                     | 仓级设计文档融合更新或仓级 ADR                                                                                                                                                           | 严禁在仓级 `docs/` 混入具体产品包的内部实现或跑分细节                                                                         |

## 2. 落盘前必须核对的两道门禁要求

写完或改完任何 `.md` 文件后, 当场执行全仓校验并确保全绿:

```shell
bun scripts/lint-doc-references.ts && bun scripts/lint-doc-examples.ts
```

重点防踩雷提示:

- 包根对外面向 npm 发布的 `README.md` / `README.zh-CN.md` 严禁引用指向包目录外的相对路径 (`../`); 内部性能设计沉淀一律进 `docs/` 而非包根 README;
- 文中提及的每一处相对链接、`§` 章节号与 `ADR NNNN` 编号必须真实存在 (假设性编号勿放在普通正文中, 可放入代码块或附带「待创建」标记);
- 若在文档中插入 `ts` 示例代码块且带行首 `import`, 必须能独立通过文档代码示例类型检查 (`bun scripts/lint-doc-examples.ts`)。

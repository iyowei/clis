# TS 转写跨语言「形似神异」暗坑核查表

> 用途: 汇总从 TypeScript / JavaScript 转写到静态与系统语言 (Rust / C / C++ / Go / Zig 等) 时, 最容易「代码看着一模一样、单元测试也能混过、上线或 `release` 后静默出事故」的高频语义差异。
>
> 使用方式: 实现者在写代码前通读一遍避坑; 对抗评审者按本表逐类构造反例证伪。

## 1. 字符串、编码与排序

| 暗坑类别             | TS / JS 既定语义                                                                  | 目标语言常见误写                                               | 防护与核验做法                                                                        |
| -------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 长度与切片单位       | `str.length` / `slice()` 基于 UTF-16 码元; 非 BMP 字符占 2 码元                   | Rust `len()` / `&s[..n]` 基于 UTF-8 字节, 非字符边界直接 panic | 按 Unicode 标量值 (`chars()`) 或显示列宽显式处理; 裁剪函数用含中文与 emoji 的用例测试 |
| 排序序与本地化       | 常见 `<` / `>` 按 UTF-16 码元序; `localeCompare` 受 locale 影响                   | 误用系统 locale 排序或未显式排序直接透传 `readdir` 顺序        | 对外输出清单显式按契约规定顺序排序; ASCII/BMP 与非 BMP 混排场景写定界用例             |
| 正则与空白折叠       | JS `\s` 含 `\u00a0` / `\ufeff` / 行分隔符等 Unicode 空白                          | Rust `is_ascii_whitespace()` 漏掉全角空格、NBSP 等空白         | 对输出净化与空白折叠使用 `char::is_whitespace()` 并核对与 JS `\s` 的具体差异集        |
| 控制字符剥离         | 逐字符剥除 C0 / DEL / C1 / bidi (`U+202A..U+202E`, `U+2066..U+2069`) / 零宽 / BOM | 只剥 `\x1b` 或仅靠 `is_ascii_control()` 漏掉 bidi 伪造字符     | 用差分模糊测试 (`dirty-line` 生成器) 注入 ANSI + RLO + 零宽 + 换行交叉比对            |
| 非 UTF-8 路径 (Unix) | Node/Bun 字符串路径在极端字节路径下可能出现替代字符或 `Buffer`                    | Rust `OsStr::to_str().unwrap()` 遇到非 UTF-8 文件名直接崩溃    | 严禁 `.unwrap()`; 比较与传递优先保 `OsStr`/`Path`, 仅在展示面按契约有损转换           |

## 2. 调试构建 vs `release` 优化构建差异

| 暗坑类别              | 典型诱因                                                          | 后果                                                         | 防护与核验做法                                                                     |
| --------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 调试断言吞副作用      | 把带状态变更的函数调用写进 `debug_assert!(validate_and_mutate())` | `debug` 测试全绿, `release` 编译期直接把整行删掉, 安全闸蒸发 | 严禁在 `debug_assert!` 中放任何业务校验或副作用; 全部验收必须在 `release` 产物重跑 |
| 整数溢出行为分叉      | Rust `debug` 溢出 panic, `release` 默认二进制补码静默回绕         | `debug` 与 `release` 对超大文件体积 / 负时间戳表现完全不同   | 统一使用 `checked_*` / `saturating_*` 显式声明溢出语义, 消除构建模式差异           |
| 未初始化/时序竞态暴露 | `release` 优化改变线程调度速度与内联布局                          | `debug` 偶发通过的并发顺序依赖在 `release` 下开始随机失序    | 最终验收必须在 `release` 产物连续跑满 3 次且逐次结果全等                           |

## 3. 数值、取整与类型强转

| 暗坑类别              | TS / JS 既定语义                                                    | 目标语言常见误写                                                                              | 防护与核验做法                                                                        |
| --------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `Math.round` 半值方向 | JS `Math.round(x)` 对 `.5` 向 `+∞` 舍入 (`Math.round(-0.5) === -0`) | Rust `f64::round()` 远离零舍入 (`(-0.5_f64).round() == -1.0`); `round_ties_even()` 银行家舍入 | 涉及小数显示/体积单位换算时, 显式验证正数、负数、边界 `.05` / `.5` 与 1023/1024 临界  |
| `NaN` / `Infinity`    | JS 数字类型天然包含 `NaN` / `±Infinity`, 比较返回 `false`           | 目标语言整数无 `NaN`, 或浮点强转 `as u64` 静默饱和归零                                        | 明确契约的合法值域; 对 JSON 反序列化来的数值校验 `is_finite()` 并与 TS 校验错误码一致 |
| 窄化强转静默截断      | JS 无 `u32`/`u16` 溢出截断概念                                      | `len as u32`、`val as i32` 在超界时静默截断高比特                                             | 禁止裸 `as` 做可能失真的窄化转换; 改用 `TryFrom::try_from` 并显式处理超界             |
| 日期与毫秒时间戳      | `Date.now()` 为毫秒级 `f64`; `olderThanDays` 按 `86_400_000` 毫秒算 | 混用秒与毫秒, 或用 `SystemTime::duration_since` 遇到未来 mtime 直接报错                       | 未来时间戳 (`mtime > now`) 必须安全返回 `false` (不 panic、不负溢出)                  |

## 4. 文件系统、软链、进程与平台差异

| 暗坑类别             | TS / JS 既定语义                                                        | 目标语言常见误写                                                   | 防护与核验做法                                                                      |
| -------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| `lstat` vs `stat`    | 扫描与安全闸强制 `lstat` (不跟进软链, 避免目录环与越权删靶)             | 误用 `fs::metadata` / `Path::is_dir()` (二者均跟进软链!)           | 全程使用 `fs::symlink_metadata` 与 `DirEntry::file_type()`; 评审重点搜 `is_dir(`    |
| 排他写盘 (`wx`)      | `writeFile(p, data, { flag: 'wx' })` 原子排他创建, 已存在即报 `EEXIST`  | 先 `exists()` 再 `write()` 引入 TOCTOU 竞态覆盖既有备份            | 必须用 `OpenOptions::new().write(true).create_new(true)` (底层 `O_CREAT \| O_EXCL`) |
| 符号链接删除语义     | 删除软链本身绝不清空其指向的目标目录                                    | 跨平台 `remove_dir_all` 在某些旧版本或自写递归里误跟进软链         | 删前先 `symlink_metadata` 判真身; 软链只 `remove_file`, 目录再递归清理              |
| 大小写折叠           | Windows 路径判定折叠大小写, POSIX 大小写敏感                            | 依赖宿主 OS 行为, 导致在 macOS/Linux 上跑 Windows 风味单测结果漂移 | 按注入的 `PathStyle` 显式 `.to_ascii_lowercase()` / `.to_lowercase()`, 不偷懒靠 OS  |
| 子进程环境变量与编码 | 调用 `du` 等外部工具须固定 `LC_ALL=C` / `LANG=C` 且直传 `argv` 禁 shell | 通过 `sh -c` 拼接命令行导致含空格/引号/元字符的路径注入            | 始终直接传参数数组 (`Command::args`), 绝不经 shell 拼接用户路径                     |
| 非 TTY stdout 缓冲   | Node/Bun `process.stdout.write` 退出前自动刷净                          | Rust `BufWriter` / C `stdout` 块缓冲在异常退出或早退时丢末尾字节   | 正常返回前显式 `flush()`, 避免直接 `process::exit()` 跳过析构与缓冲区冲刷           |

## 5. 格式化、内存与资源清理

| 暗坑类别              | 典型诱因                                                       | 后果                                                        | 防护与核验做法                                                                |
| --------------------- | -------------------------------------------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 外部文本二次格式化    | C `printf(msg)` 或把错误文本拼进模板占位再渲染                 | 路径含 `%s` / `{}` 时崩溃或内容被篡改                       | 始终使用固定格式字面量 (`eprintln!("{}", msg)` / `fputs`)                     |
| 提前返回漏清理        | TS `try { ... } finally { cleanup() }` 转写时改成提前 `?` 返回 | 出错路径残留临时目录、锁文件或半写入占位文件                | 把需要清理的资源封装成带 `Drop` (Rust) 或 `defer` (Go/Zig) 的守卫结构体       |
| `JSON.stringify` 差异 | JS 序列化自动忽略值为 `undefined` 的对象字段, `null` 则保留    | 目标语言结构体序列化出 `"details": null` 与语料精确比对不符 | 对可选字段加条件省略 (如仅 `Some(v)` 时输出键), 严格对齐 API harness 输出协议 |

## 配置规格

配置文件位置 (平台自适应, 不写死):

| 平台                 | 默认路径                                   |
| -------------------- | ------------------------------------------ |
| Windows              | `%APPDATA%\sweep-node-modules\config.json` |
| 其余 (macOS / Linux) | `~/.config/sweep-node-modules/config.json` |

优先级: `--config <path>` > 环境变量 `SWEEP_NM_CONFIG` > 平台默认 (测试与受控环境也用这条链换配置); 见 [ADR 0007](../../../packages/sweep-node-modules/docs/adrs/0007-platform-portability.md)。本次实际生效的路径和文件是否存在, 用 `sweep-nm config` 查询 (见 [命令面与输出](../../../packages/sweep-node-modules-cli/docs/designs/cli-surface.md))。

```json
{
  "roots": ["/Users/iyowei/workspace/development"],
  "exclude": ["my-kits"],
  "include": []
}
```

| 字段      | 类型       | 语义                                                                                                                                     |
| --------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `roots`   | `string[]` | 扫描根, 任意多个; 按 realpath 去重 (防止嵌套或重复写导致重复统计)                                                                        |
| `exclude` | `string[]` | 排除名单; 从根到命中点, 任意一级目录名命中就跳过; 不写时取内置默认名单 (见下「默认排除名单」); 只要写出来 (包括空数组), 就以用户名单为准 |
| `include` | `string[]` | 包含名单 (白名单); 命中才纳入, 判定方式和 `exclude` 一样; 不写就等于 `[]` (即不过滤)                                                     |

- 排除按「任意一级目录名命中」判定: 写 `my-kits` (项目名) 或 `url-tool` (容器名) 都算命中; 多排除 = 少删, 天然更安全; 没命中任何目录的名字会在 stderr 给出警示 (保命名单不得静默失效); 例外是内置默认名单里的项、以及写出来但和默认名单同名的项, 这两类零命中也不告警 (这类零命中属于平台和用户环境的事实, 不是可修正的拼写错误; 见 [行为契约](../protocol/behavior-contract.md) BC-09 与下「默认排除名单」)。
- 包含的判定和排除完全一样 (任意一级命中就纳入), 只是方向相反: 多包含 = 多删; 不写就是空数组, 等于不过滤, 和当前不带白名单的行为一致。
- `node_modules` 与 `.git` 写进 `exclude` 或 `include` 都会被静默剔除, 永不生效 (不报错、不告警、不阻断), 和不写一样; 两者的理由不同: `node_modules` 是本工具的目标 (写进排除等于排掉唯一的操作目标, 写进包含就永远零命中), `.git` 在扫描时本来就会被跳过 (留在名单里只会换来一条结构性假告警: 这个目录明明存在, 却被报成「未匹配」)。剔除之后 `include` 若为空数组, 等于不过滤。
- **优先级**: 同一级目录名同时命中两份名单时, **排除优先** (先按白名单筛出候选, 再把命中排除的从候选里排掉, 即「命中排除 → 无条件跳过」)。
- **命中计数独立于优先级**: 名字命中白名单即计入命中数, 随后被排除截走的仍计入 (截走不等于没匹配上); 「未匹配」警示以这个计数为零为准, 不然被截走的名字会以零命中报成「未匹配」, 误导用户去查一个根本不存在的拼写问题。
- 包含名单里的名字没命中任何目录时, 同样在 stderr 警示: 白名单里写错名字会让扫描结果直接为空, 这种错比排除写错更不能静默。
- 命令行 `--exclude` / `--include` 会和配置合并 (见 [命令面与输出](../../../packages/sweep-node-modules-cli/docs/designs/cli-surface.md))。
- **`roots` 在删除侧必须是真实路径**: 根和它的祖先链必须过安全闸的第五道不变量 (从文件系统根的一级子目录起, 逐级到配置里的根自身, 每级都 lstat 确认是真目录; 任一级是符号链接就整批拒绝, 见 [删除安全闸](deletion-guard.md)「校验不变量」5); 扫描侧不受这一条限制 (根是符号链接也照常扫描, 显式即授权), 所以同一份配置下出现「预览有清单、`--yes` 被拒」是预期行为, 不是缺陷。macOS 上 `/tmp`、`/var` 这类系统链接, 必须改写成不含符号链接的真实路径 (如 `/private/tmp/x`); 被拒时的文案会自带改写指引。
- **`roots` 里声明挂载点, 就能解除 on-path 跨设备跳过**: 目标与它所属的根不在同一个文件系统时 (跨设备), 删除侧会逐条跳过; 其中挂载点夹在根和目标之间的那种, **把中间的挂载点声明为独立根**就能清理: 归属取最具体的根, 设备比对也跟着以这个根为参照; 目标本身就是挂载点的那种, 声明根不起作用, 只能先卸载那个卷。见 [行为契约](../protocol/behavior-contract.md) BC-41 与 [删除安全闸](deletion-guard.md)「设备边界」。
- 配置缺失与 `sweep-nm init` 的行为见下方「配置初始化模型」。

### 默认排除名单

`exclude` 字段不写时取内置的保守名单 (词表在 API 包 `src/config.ts` 的 `DEFAULT_EXCLUDE`, 单一事实来源):

| 分组                  | 目录名                                                                        | 挡在这里的理由                                                                                                                                                                                                                                                                            |
| --------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 包管理器 / 版本管理器 | `.bun` `.npm` `.pnpm-store` `.yarn` `.nvm` `nvm` `.fnm` `.volta` `.asdf` `.n` | 这些根下是工具自身的安装树: bun 的 `install/global` (本机实测 4.25 GB / 1627 包, 且本工具自身常装于其中)、npm 的 `_npx` 缓存、版本管理器的 `lib/node_modules` (用户全局包清单的唯一所在)、pnpm / yarn 的 store。删后无法由项目级重装恢复, ADR 0002 的「可恢复, 非数据损失」前提在此不成立 |
| 编辑器 / IDE          | `.vscode` `.vscode-insiders` `.vscode-server` `.cursor` `.antigravity`        | 每个扩展目录都自带 `node_modules`, 属于应用自己而不是用户项目; 重装扩展才能还原                                                                                                                                                                                                           |
| 系统 / 应用数据根     | `Library` `.local` `.config` `.cache` `.claude`                               | macOS 的 `Library` 与 XDG 根下散落应用私有安装树 (macOS 的 fnm、各类应用的插件目录); 本机实测命中 `Library/Application Support/Kap/plugins` 与 `.config/opencode`                                                                                                                         |

- **判定规则和用户名单完全一致** (任意一级目录名命中就跳过), 只是默认值不再为空; 名单里的项随平台和用户环境而不同 (Linux 上就没有 `Library`), 所以**零命中不告警**: 这和手写名字拼错不一样, 后者是可修正的输入错误 (见 [行为契约](../protocol/behavior-contract.md) BC-09);
- **用户可覆盖**: 配置文件里明确写出 `exclude` (哪怕写空数组) 就以用户名单为准, 默认名单不参与; 想「在默认之外再加」, 就在名单里带上要保留的默认项。覆盖不会造成漏放: 删除侧另有一道不受用户配置影响的「语义闸」(疑似安装树默认不进删除批, 见 [删除安全闸](deletion-guard.md));
- **保守取向**: 宁可挡住个别同名的真实项目 (用户可以从配置里删掉这一项), 也不漏放安装树; 这张词表是保守基线, 不是完备清单: 没收录的应用私有根 (比如某个工具在 home 下的专属目录) 由用户按需补进 `exclude`。

## 配置初始化模型

- **首次运行且没有配置**: TTY 下自动进入初始化向导; 非 TTY 下静默回退到「以当前工作目录为根」, 并明确提示 (含 `sweep-nm init` 指引), 不询问 (免得卡死脚本和以后的定时任务)。
- **`sweep-nm init`**: 手动重进向导, 重写配置; 非 TTY 下直接报错退出 (不能静默地报「成功」)。
- **向导内容**: 三问 (扫描根, 默认家目录; 排除名单, 空答取内置默认名单: 显式写出的 `exclude` 会接管默认值, 若空答回填成空数组, 就等于「一路回车把默认保护写没了」, 与默认值本身相悖; 包含名单, 可留空) → **逐根校验 (存在性与根锚点形态)** (不存在的根、以及落在符号链接路径上的根, 当场提示并重问; 坏输入挡在落盘之前; 后一种在删除侧必然整批被拒, 向导按同一套判定提前把它暴露出来, 见下方「配置规格」的 `roots` 条目) → **回显解析结果并确认** (默认 Y) → **落盘前锚点检查 (写入侧)** (配置路径或它的祖先链上有符号链接, 就拒掉并重问「确认写入?」, 见下条) → 落盘并**回显配置全文** (路径行先做家目录缩写、再过净化, 与其余外部路径的回显一样; 正文与落盘文件内容一致、整体缩进 2, 方便当场核对和复制; 这个回显块**刻意不净化**: 它和落盘文件逐字一致, 这是供对照复制的承诺, 净化会破坏这个承诺, 界线见 [行为契约](../protocol/behavior-contract.md) OF-14 的排除项); 输入解析支持 `~` / `~\` 展开, 成对引号里的空格会保留, 未配对的引号按普通字符处理。
- **向导形态**: 顶栏 `▍ SWEEP-NM  初始化向导` + 中性块说明行 (`░` 前缀 + 压暗) + 压暗的提示段 (`[默认: …]` / `[回车采用默认名单 (N 条)]` / `[回车跳过]` / `(Y/n)`); 「回显解析结果」从 JSON 形态改成人话 `将写入 N 个扫描根 · 排除 M 条 · 包含 K 条` (N / M / K 由解析结果实时计数), 落盘 JSON 全文的回显仍保留在后面 (内容与文件一致、整体缩进 2); 校验失败的行把红色 `✗` 放在行首, 落盘成功的行把绿色 `✓` 放在行尾。完整规格 (含向导顶栏的字段取舍与 TTY 专属边界) 见 [命令面与输出](../../../packages/sweep-node-modules-cli/docs/designs/cli-surface.md)「输出规格 · `init` 向导」。
- **向导写入轮强制预览**: 本轮刚生成配置时, **即使带 `--yes` 也只预览** (stderr 说明), 复核过清单才能再次运行执行; 「看清再删」在首次使用的路径上同样成立。
- **覆盖保护**: 配置已存在时先确认是否覆盖 (`配置已存在 (<path>), 是否覆盖? (y/N)`, 提示段压暗), 默认否; 中途取消统一输出「已取消, 未写入配置」, 不落盘; 取消 / 拒绝分支不加色块前缀 (中性终态, 加色块会附上「成功 / 失败」的误导语义)。
- **落盘前锚点检查 (写入侧)**: 用户确认写入后、任何写动作 (包括建目标目录) 之前, 对配置路径 (旗标 / 环境变量 / 平台默认给的拼写) 及其祖先链逐级 lstat; 任一级是符号链接 (含悬空链接) 就用红色 `✗` 给出链接位置和配置拼写, 并重问「确认写入?」(形式和逐根校验一样), 路径修好前不写一个字节。配置路径是悬空链接时, 覆盖判重 (`lstat` 语义, 不跟进末段) 同样算「已存在」, 所以这类路径会先出「是否覆盖」一问, 之后才在写入侧被拒。理由: 写入会跟随符号链接, 被完整改写的是链接指向的目标 (任意可写文件), 而不是配置位置本身; 而回执报的仍是用户给的那个拼写, 事后看不出实际写到哪。这一步的判定和删除侧的根锚点共用同一实现 (`guard.ts` 的 `firstSymlinkOnTarget`, 见 [行为契约](../protocol/behavior-contract.md) BC-40), 系统固有的链接 (macOS 的 `/tmp`、`/var`) 同样命中, 改写成不含符号链接的形式就放行; 这与下方「配置规格」`roots` 条目的真实路径要求同源。
- 实现边界与决策见 [ADR 0004](../../../packages/sweep-node-modules/docs/adrs/0004-config-initialization-wizard.md)。

## 错误与边界

| 场景                                           | 处置                                                           |
| ---------------------------------------------- | -------------------------------------------------------------- |
| 显式来源 (旗标 / 环境变量) 指向不存在的文件    | 硬报错 `配置不存在 (<path>)` + 退出码 1 (不得静默回退去扫 cwd) |
| 平台默认来源缺失                               | 软处理: 进向导 (TTY), 或回退扫 cwd (非 TTY)                    |
| 配置损坏 (JSON 解析失败 / 空文件 / 字段类型错) | 逐字段具体报错 (含路径与病因) + 退出码 1                       |

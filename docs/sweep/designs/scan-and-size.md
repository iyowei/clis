## 扫描算法

1. 从每个根开始递归遍历; 某一级目录名正好是 `node_modules` 时, 把它的父目录记为「项目」, 并且**不再往下钻** (嵌套的情况天然被一并覆盖);
2. 符号链接目录不跟进 (防目录环, 也防意外跳出根之外);
3. 排除在进入目录时判定: 路径中任意一段命中 `exclude`, 整棵子树跳过;
4. 多个根的结果合并, 按 realpath 去重;
5. 跳过 `.git` 目录 (里面不可能有项目依赖, 直接省掉整棵子树的遍历开销);
6. 根目录预检按错误码区分原因 (不存在 / 不可读 (权限不足) / 不是目录 / 其他带错误码的情况), 单个根失效不影响其余根;
7. 根与命中目标的去重键按平台惯例统一 (win32 下大小写折叠, 与安全闸同源);
8. 根本身就叫 `node_modules` 时不记录 (根只当容器看, 本身不算项目);
9. 根本身是符号链接时照常扫描 (显式写进配置即视为授权), 重复由 realpath 去重兜住。**这条仅限扫描侧**: 删除侧要求真实路径形态作为信任锚 (配置里的拼写逐级都必须是真目录), 所以同一份配置下, 预览有清单、`--yes` 被整批拒绝, 是预期行为, 见 [删除安全闸](deletion-guard.md)「校验不变量」5;
10. 两份名单各自输出命中统计 (`excludeMatches` / `includeMatches`, 没命中的名字也在列): 破坏性动作的「保命名单」反馈通道, 名字打错不能被悄悄忽略 (白名单写错的后果更重: 筛选结果直接为空)。例外: **内置默认排除名单里的项** (见 [配置与初始化](config-and-initialization.md)「默认排除名单」) 零命中时不告警: 这些名字随平台与用户环境而变, 不是改一下拼写就能对上的问题 (过滤逻辑在 `cli.ts` 的 `collectNameNotes`)。
11. 包含判定 (白名单) 与排除用同一套规则: 从根到 `node_modules` 的任意一级目录名命中 `include` 才纳入, 空数组不过滤; 同一级同时命中两份名单时**排除优先** (先按白名单筛出候选, 再从候选里排掉命中排除的)。**命中计数独立于排除优先**: 名字命中白名单即计入 `includeMatches`, 随后被排除截走也仍然计入 (截走不等于没匹配上), 免得被截走的名字以零命中报成「未匹配」, 让人去排查一个根本不存在的拼写问题。

**实现裁定 (基准 r1-r4)**: 三个候选 (手写剪枝 / 原生 `recursive` 后过滤 / 有界并发) 都通过契约与鲁棒套件后, 由基准实测裁定, 取**有界并发** (CONCURRENCY=32): 真实工作区 (2026-09-23 实测, 约 3.8 万目录; 现场容器现已不存在) 从 3.4s 降到 0.67s (4.8×); 并发上限经拐点扫描定下 (先粗扫一轮 8/16/32/64/128/256, 再空载细扫 4/8/16/32/64), 取 32 (性能平台期的起点; 从 256 起中位数开始回退)。原生 `recursive` 因为「会跟进符号链接 + 遇到第一个不可读目录就中断整次调用」与契约硬冲突, 实测后被弃用。候选之间的一致性由契约套件里的「候选间一致」对撞持续钉住 (2026-09-24 补入, 随即暴露并修复了 `native` 的一处排除名单判定偏差)。

## 体积统计 (已裁定: 策略 A 双轨)

- **统计口径**: du 快路径 = 磁盘占用 (macOS / Linux, 与 Finder 一致); 纯实现基线 = 逻辑字节 (没有 du 的平台, 与 Explorer 的「大小」列一致): 两者各自对齐所在平台的原生惯例;
- **快路径**: unix 平台上有 `du` 时, 把全部命中路径汇总起来, **只启动一次** du (`du -sk -- <paths...>`, 其中 `--` 终止符防止以 `-` 开头的路径被当成选项);
- **基线**: 没有 du 的平台走纯 JS 递归统计; 门面 (`size.ts`) 用 `findDu()` 探针二选一; win32 一律按无 du 处理: 探针是 POSIX 绝对路径, 在 Windows 上会被解析成「当前盘根」下的 `usr\bin\du` (如果那个盘上恰好有同名的外来程序, 就会被启动), 所以 `findDu` 的平台守卫在 win32 直接返回 null (行为契约 EC-03);
- 结果分四桶: `entries` (可测量) / `unmeasured` (存在但测不到, 比如权限不够; **不能悄悄移出清单**: 下游以占位行展示, 并计入失败) / `gone` (扫描命中、测量时已经不存在 (BC-13) 的路径; 「不存在」既不产生字节, 也不是「存在但测不到」, 所以单列一桶, 与 `SIZE_TARGET_VANISHED` 告警同源同判定) / `warnings` (非致命, 比如子目录降级); `entries` ∪ `unmeasured` ∪ `gone` 三者合起来恰好是全部输入路径, 且两两不相交;
- **解析防御**: du 输出按行解析后做**多重集一致性校验** (解析出的路径必须与输入一一对应), 对不上就整体降级为 `unmeasured` (降级时会附带一条按输出形态归类的告警, 「什么都没删」因此有据可查, 不会悄无声息); 含 `\n` / `\r` 的目标在进命令行前就被拒 (防止路径里的换行把输出拆行、注入多余条目);
- **输出形态 (已核实, 2026-09-27)**: du 只在 stdout 是终端时, 才会按 shell-escape 风格给文件名加引号 (`When standard output is a terminal, file names are quoted using the shell-escape style`, GNU coreutils 手册 du 一节; 源码里由 isatty 控制, 9.12 之前的版本没有这层引用逻辑), 本快路径用管道捕获 stdout、永远不是终端, 所以文件名一律按输入原样成行 (TAB / ESC / 引号等都原样保留; 已实测 GNU du 9.12 与 BSD du, 且非终端下 `QUOTING_STYLE` 环境变量也不起作用)。所以一致性校验只可能在两种情况失败: 行结构被破坏 (注入), 或者上面这个前提被推翻; 两种情况都一律整体降级 (fail-safe), 不逐条采信;
- 统计不跟随符号链接 (与扫描同一策略); 不允许逐个目标各启动一次 du, 也不允许逐个目标单独遍历;
- **统计口径与删除面的设备差异 (登记, 2026-09-27)**: 体积按目标目录的**整体占用**计算, 包含它下面挂着的子挂载点 (即另一文件系统上的字节): 体积口径回答的是「这里占多大」, 删除面回答的是「能不能删」, 两者不是一回事。删除面对「目标与根不在同一设备」的目标默认跳过 (见 [删除安全闸](deletion-guard.md)「设备边界」), 体积则照常展示 (供用户判断要不要把它声明成独立根再清理)。**没有采纳 `du -x` 的理由**: `-x` 参照的设备是命令行上直接给出的那个目录本身 (实测: 对挂载点本体, `du -skx` 与 `du -sk` 同值 12 KB; 对它的上层目录则 16 KB → 4 KB), 所以它只能改变「目标内部含子挂载点」这类目标的数字; 而这类目标的删除并不能靠挂载点整体拦下: 挂载点自身删不掉 (最后以 `EBUSY` 收场), 卷里的内容在 bun 下却可能已经被探进去删掉了 (两个运行时的对撞实测见 [删除安全闸](deletion-guard.md)「残余风险」), 这个目标整体算失败, 它的字节不进执行报告的「释放」总量; 加 `-x` 换不来口径上的对齐, 反而让纯 JS 候选 (逐目录遍历, 没有对应语义) 与快路径之间多出一处分歧。目标内部有子挂载点时的删除面残留与候选修法, 另见该节。

## 性能要点 (热路径是目录遍历, 性能不能差)

- 用 `readdir withFileTypes` 直接拿到条目类型, 省掉对每个条目单独 `lstat`;
- 命中 `node_modules` 即剪枝, 不再往下钻;
- 跳过 `.git` 目录; 符号链接目录不跟进;
- 遍历走**有界并发协作池** (显式栈 + 在途任务计数, 不用递归; 瓶颈是 readdir 的往返延迟, 约 98µs/目录, 目标是把 I/O 队列填满, 而不是堆并行度);
- 体积统计批量完成或单遍走完, 不逐个目标各启动一次。

## 错误与边界

| 场景                                       | 处置                                                                                                        |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 目录不可读                                 | 告警并跳过, 不中断                                                                                          |
| 某根不存在 / 不可读 / 不是目录             | 按具体原因给出对应文案, 跳过该根                                                                            |
| 存在但测不到体积                           | 归 `unmeasured`, 下游以占位行展示并计入失败 (退出码 1)                                                      |
| du 输出与输入集合不符 / 目标无法对应到输入 | 前者整批降为 `unmeasured`, 后者仅该目标降为 `unmeasured` (前者附一条按输出形态归类的告警); 均不进入删除批次 |
| 路径过深超出 `PATH_MAX`                    | `realpath` 退化为按字面路径处理 (两个候选实现表现一致); 去重退化为按字面拼写相同来判重, 属已知边界          |

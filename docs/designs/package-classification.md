# 包分类与发布协议 (Package Classification)

> 文档类型: 仓库级设计
> 适用对象: 本仓维护者与 AI Agent
> 前置: [集合仓定位](collection-positioning.md)

## 三类包

本仓每个包都恰好属于下面三类之一:

| 类别           | 判定依据 (确定性字段)                                                 | 发布     | 例子                             |
| -------------- | --------------------------------------------------------------------- | -------- | -------------------------------- |
| **CLI 工具**   | `package.json` 有 `bin` 字段                                          | 发 npm   | `@iyowei/sweep-node-modules-cli` |
| **公开库**     | 没有 `bin`, 且非 `"private": true`                                    | 发 npm   | `@iyowei/sweep-node-modules`     |
| **仓内私有库** | 没有 `bin`, 且自身 `package.json` 标 `"private": true` (npm 原生字段) | 不发 npm | (待首个私有库出现)               |

分类全看确定性字段, 没有人工维护的分类清单: 一个包属于哪一类, 由 `bin` 字段和 `private` 字段**直接推出**, 不需要在别处复述。`"private": true` 也是发布链侧的隔离机制: multi-semantic-release 的 `ignorePrivate` 默认开启, private 包不进它的加载面 (双保险)。

边界: 首发前的生成器包也带 `"private": true`, 但它不属本表的「仓内私有库」类: 它是待发布包, 首发时移除该标记并完成首发 (流程见[开发指南](../development.md)「发布」章的「新包首发路径」, `create-clis` 已完成首发); 「仓内私有库」是不发 npm 的长期类别, 两者只是共用同一个字段。

## 各类包的工程要求

| 要求                              | CLI 工具                 | 公开库       | 仓内私有库 |
| --------------------------------- | ------------------------ | ------------ | ---------- |
| 双语 README (英文为主)            | 必须                     | 必须         | 不需要     |
| 发布自证闸门 (`verify:release`)   | 必须                     | 必须         | 不需要     |
| 金样本语料 (conformance 档)       | 看工具需要               | 看对外暴露面 | 不需要     |
| 契约测试 + 双载体测试             | 必须                     | 必须         | 必须       |
| 通用闸门 (引用 / 示例 / 散落备份) | 仓库统一跑, 不用按包配置 |              |            |

「看工具需要 / 看对外暴露面」怎么定档、豁免怎么登记, 沿用转写契约套件的覆盖表纪律 (见 `../sweep/protocol/README.md`)。

## 新增一个包的最低门槛

1. 包放在 `packages/` 下, 名字用 `@iyowei/<name>` (工具的配套包可以叫 `<name>-cli`);
2. 按上表把它这一类该有的工程件补齐;
3. 依赖方向要符合[依赖方向纪律](dependency-direction.md);
4. 私有库还要在自身 `package.json` 标 `"private": true` (怎么判定、怎么标注见上面的分类表);
5. 在根 README 的包列表里加一行。

## 与发布链的边界

版本怎么判、发布走哪条通道、自证怎么做, 都归既有的发布链设计管 (`../development.md` 与 ADR 0009 / 0010); 本文档只规定谁发布、每类包按什么要求发布, 不改发布链的行为。

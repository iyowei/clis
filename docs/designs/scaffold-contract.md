# 生成器契约 (Scaffold Contract)

> 文档类型: 仓库级设计
> 适用对象: 本仓维护者与 AI Agent
> 前置: [生成器包](scaffold-package.md)与[模板快照机制](scaffold-template-snapshot.md); 档位见[能力分档](capability-tiers.md)

## 命令形态

```
<runtime> create clis [dir] [flags]
```

- `npm create clis` / `pnpm create clis` / `bun create clis` / `bunx create-clis` 都可以 (create 约定的三种分发入口, 各自的官方文档都已核验);
- `dir` 默认是当前目录下以项目名命名的子目录; 目标目录已存在且非空就直接拒绝 (**不做覆盖**, 也没有 `--force` 逃生口: 覆盖已有目录的风险远大于那点便利)。

## 变量

生成器收集五个变量, 与快照词汇表一一对应:

| 变量     | 交互问答 / 旗标     | 默认值与校验                                         |
| -------- | ------------------- | ---------------------------------------------------- |
| 项目名   | 位置参数或 `--name` | 没有默认值; 校验 kebab-case 且目录可用               |
| scope    | `--scope`           | 默认不带 scope (裸包名)                              |
| bin 名   | `--bin`             | 默认由项目名派生 (`<name>` 的短形态); 校验命令行可用 |
| owner    | `--owner`           | 默认取 git 全局 `user.name`                          |
| 仓库地址 | `--repo`            | 默认 `https://github.com/<owner>/<name>`             |

## 档位

`--tier core|standard|full` (默认 `standard`)。各档含义与裁剪范围见[能力分档](capability-tiers.md)。

## 流程 (按先后顺序)

1. **收集**: 无旗标时交互问答 (readline 直问直答, 不依赖交互库, 与本仓初始化向导同风格); 有旗标时零交互; 两种方式都会先做合法性校验;
2. **复制与载体还原**: 取模板快照复制进目标目录, 并把随包的载体名 (`_gitignore` / `_npmrc`) 还原成真实名 (npm 面包机制按文件名剔除这两个真实名, 见[技术债登记](tech-debt.md) TD-05);
3. **按档裁剪**: 按档裁剪装备 (见[能力分档](capability-tiers.md));
4. **替换变量**: 把词汇表里列的每种形态都替换一遍;
5. **格式化收口**: 替换与裁剪会改变行宽与结构 (如单元素数组), 产物统一过一遍 prettier 回到稳定态 (生成物自身 `format-check` 的前提); 用生成器自带的 prettier 与同版本插件, 此刻产物尚未安装依赖;
6. **自检**: 生成物再扫一遍, 确认变量零残留 (快照那边已经保证过模板干净, 这一步是替换完整性的第二道防线); 自检前置于收尾 (残留未清就不做 git init / 装依赖, 免坏产物被收尾动作固化);
7. **收尾**: 按旗标决定是否执行 `git init` (默认执行) 与依赖安装 (默认执行, `--no-install` 关闭);
8. **交付**: 打印 next steps (进入目录 → `bun run ci` 验证全绿 → 从[集合仓定位](collection-positioning.md)读起, 开始改造)。

## 旗标汇总

`--name` `--scope` `--bin` `--owner` `--repo` `--tier` `--no-git` `--no-install` `--yes` (全部取默认值, 零交互)。

经 `npm create` 调用时, 旗标要写在 `--` 后面 (`npm create clis -- --name x`), 这是 npm 生态的既有行为, 生成器不用管。

## 失败处理

- 校验失败 / 目录冲突 / 复制或替换出错: 打印原因并以非零退出码结束, 已产生的半成品目录如实指出 (不悄悄清理, 用户可自行查看);
- 生成器自身崩溃: 与既有 CLI 包同款的崩溃诊断纪律 (stderr 打印诊断 + 非零退出码)。

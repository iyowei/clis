# 文档分层协议 (Docs Layering)

> 文档类型: 仓库级设计
> 适用对象: 本仓维护者与 AI Agent
> 前置: [集合仓定位](collection-positioning.md); 决策记录见 [ADR 0011](../adrs/0011-docs-and-adr-layering.md)

## 判据

文档归哪一级, 看它**服务谁**:

- **只服务单个包** (该包的实现细节、该包的对外面) → **包级**, 落 `packages/<pkg>/docs/`;
- **服务产品整体、跨包横切, 或属仓库机制** → **仓库级**, 落 `docs/`。

## 两级结构

### 仓库级 (`docs/`)

- 索引: `README.md` (总入口, 含成员包入口的外链区);
- 工程与治理: `development.md` / `adrs/` (仓库级 ADR) / `designs/` (仓库级设计组 + 产品级文档区);
- 产品级文档的当前住所: 在集合出现第二个产品之前, 成员产品的跨包文档留在 `designs/` 的「产品设计」组 (演进触发点见下)。

### 包级 (`packages/<pkg>/docs/`)

- **入口固定为 `docs/README.md`**: 包定位一句话 + 包内文档清单 (含包级 ADR)+ 回链仓库级核心 (索引 / 总纲 / 与包相关的设计文档);
- 单包专属设计文档与包级 ADR 落在此目录 (包级 ADR 进 `docs/adrs/`);
- 包级 docs 不进 npm 发行包 (发行面由各包 `files` 白名单与发布自证闸门钉死, 消费者面看包根 README)。

## 外链标准位 (关联关系的固定通路)

AI 与人类读取时的固定走法, 仓库级与包级**双向**织链:

```
docs/README.md ──(成员区)──▶ packages/<pkg>/docs/README.md   (全部成员一律列出)
packages/<pkg>/docs/README.md ──(回链)──▶ docs/README.md + 本包相关设计文档/ADR
designs/README.md ──(产品文档条目)──▶ 下沉到包内的篇目改外链其实际位置
```

外链的有效性由引用闸门 (`scripts/lint-doc-references.ts`, 相对链接存在性) 兜底; 纯粹的文字指代 (如代码注释里的「见 X 篇」) 由变更影响面扫描在改动时人工核对。

## ADR 分层

- **编号全局单调递增, 跨两级唯一**: 新 ADR 无论归属哪级, 编号从既有最大值续排; 已发布编号永不重编 (全仓「ADR NNNN」文字引用因此永远有效);
- **归属判据同上** (单包/产品决策 → 包级; 仓库机制与结构 → 仓库级);
- **查找面**为两级并集: `docs/adrs/` + `packages/*/docs/adrs/` (引用闸门按此扩展);
- **索引**: 仓库级索引 `docs/adrs/README.md` 列全部编号 (包级行外链到包内实际位置); 包级 ADR 不再另建索引文件, 由包 `docs/README.md` 的清单承载。

## 本批归属判定 (迁移执行依据)

| 内容                                                                      | 判定                | 去向                                     |
| ------------------------------------------------------------------------- | ------------------- | ---------------------------------------- |
| `api-surface`                                                             | 单包对外面 (API 包) | `packages/sweep-node-modules/docs/`      |
| `cli-surface`                                                             | 单包对外面 (CLI 包) | `packages/sweep-node-modules-cli/docs/`  |
| 总纲 / 加固 / 安全账 / 架构总览 / 转写套件 (`protocol/`) / 各验收设施设计 | 产品整体或跨包      | 留仓库级 (designs 产品组 / protocol)     |
| ADR 0001 / 0002 / 0003 / 0004 / 0007 / 0008                               | 产品决策            | `packages/sweep-node-modules/docs/adrs/` |
| ADR 0005 / 0006 / 0009 / 0010                                             | 仓库机制与工程策略  | 留 `docs/adrs/`                          |

## 演进触发点

出现第二个产品时, 重新评估一次: 产品级文档是否收拢为「成员区」或下沉主包。现在不做 (避免为想象的需求迁就结构)。

## 与生成器/模板的关系

模板中的 docs 骨架即本协议的物化: 仓库级骨架 (索引 / adrs / designs 空组) + 每包 `docs/README.md` 入口 + 产品区占位; 结合[模板快照机制](scaffold-template-snapshot.md)的「重置类」处置执行。

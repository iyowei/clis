## 配置规格

配置文件位置 (平台自适应, 不写死):

| 平台                 | 默认路径                                   |
| -------------------- | ------------------------------------------ |
| Windows              | `%APPDATA%\sweep-node-modules\config.json` |
| 其余 (macOS / Linux) | `~/.config/sweep-node-modules/config.json` |

优先级: `--config <path>` > 环境变量 `SWEEP_NM_CONFIG` > 平台默认 (覆盖通道亦服务测试与受控环境); 见 [ADR 0007](../../packages/sweep-node-modules/docs/adrs/0007-platform-portability.md)。本次实际生效的路径与文件存在与否用 `sweep-nm config` 查询 (见 [命令面与输出](../../packages/sweep-node-modules-cli/docs/designs/cli-surface.md))。

```json
{
  "roots": ["/Users/iyowei/workspace/development"],
  "exclude": ["my-kits"],
  "include": []
}
```

| 字段      | 类型       | 语义                                                                                                                              |
| --------- | ---------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `roots`   | `string[]` | 扫描根, 任意多个; 按 realpath 去重 (防嵌套或重复写导致重复统计)                                                                   |
| `exclude` | `string[]` | 排除名单; 从根到命中点的任意一级目录名命中即跳过; 缺省取内置默认名单 (见下「默认排除名单」), 显式写出 (含空数组) 即以用户名单为准 |
| `include` | `string[]` | 包含名单 (白名单); 命中才纳入, 口径与 `exclude` 同款; 缺省视为 `[]` (即不过滤)                                                    |

- 排除语义取「任意一级目录名命中」: 写 `my-kits` (项目名) 或 `url-tool` (容器名) 都成立; 多排除 = 少删, 天然落在安全方向; 未命中任何目录的名字会在 stderr 给出警示 (保命名单不得静默失效), 例外是内置默认名单项与显式写出的同名项零命中不告警 (该项零命中属平台与用户环境事实, 不是可修正的拼写错误; 见 [行为契约](../protocol/behavior-contract.md) BC-09 与下「默认排除名单」)。
- 包含语义与排除同款口径 (任意一级命中即纳入), 方向相反: 多包含 = 多删; 缺省空数组 = 不过滤, 与不带白名单的今日行为一致。
- `node_modules` 与 `.git` 写进 `exclude` 或 `include` 都会被静默剔除, 永不生效 (不报错、不告警、不阻断), 与不写等价; 两者理由不同: `node_modules` 是本工具的目标 (列入排除等于排掉唯一操作目标, 列入包含则永久零命中), `.git` 被扫描恒定跳过 (留在名单里只会换来一条结构性假告警: 该目录客观存在, 却报成「未匹配」)。剔除后 `include` 为空数组 = 不过滤。
- **优先级**: 同一级目录名同时命中两份名单时**排除优先** (先按白名单筛出候选, 再从候选里排掉命中排除的, 即「命中排除 → 无条件跳过」)。
- **命中计数独立于优先级**: 名字命中白名单即计入命中数, 随后被排除截走的仍计入 (截走不等于没匹配上); 未匹配警示以该计数为零为准, 否则被截走的名字会以零命中报成「未匹配」, 诱导用户去排查不存在的拼写问题。
- 包含名未命中任何目录时同样在 stderr 警示: 白名单写错名字会让扫描结果直接为空, 比排除写错更不能静默。
- 命令行 `--exclude` / `--include` 与配置合并 (见 [命令面与输出](../../packages/sweep-node-modules-cli/docs/designs/cli-surface.md))。
- **`roots` 在删除侧须为真实路径形态**: 根及其祖先链要过安全闸的第五道不变量 (自根的一级子目录至根自身逐级 lstat 判真目录, 任一级为符号链接即整批拒绝, 见 [删除安全闸](deletion-guard.md)「校验不变量」5); 扫描侧不受此限 (根为符号链接照常扫描, 显式即授权), 故同一配置下「预览有清单、`--yes` 被拒」是预期行为而非缺陷。macOS 上 `/tmp`、`/var` 等系统链接形态须写成 realpath 形态 (如 `/private/tmp/x`), 拒绝文案自带改写指引。
- **`roots` 声明挂载点即解除 on-path 跨设备跳过**: 目标与所属根不同文件系统时 (跨设备) 删除侧逐条跳过, 其中入口在根与目标之间的形态, **把中间的挂载点声明为独立根**即可清理: 归属取最具体根, 设备比对随之以该根为参照; 目标本体即挂载点的形态不受声明根影响, 须先卸载该卷。见 [行为契约](../protocol/behavior-contract.md) BC-41 与 [删除安全闸](deletion-guard.md)「设备边界」。
- 配置缺失与 `sweep-nm init` 的行为见下方「配置初始化模型」。

### 默认排除名单

`exclude` 字段缺省时取内置保守名单 (词表落在 API 包 `src/config.ts` 的 `DEFAULT_EXCLUDE`, 单一事实来源):

| 分组                  | 目录名                                                                        | 挡在这里的理由                                                                                                                                                                                                                                                                            |
| --------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 包管理器 / 版本管理器 | `.bun` `.npm` `.pnpm-store` `.yarn` `.nvm` `nvm` `.fnm` `.volta` `.asdf` `.n` | 这些根下是工具自身的安装树: bun 的 `install/global` (本机实测 4.25 GB / 1627 包, 且本工具自身常装于其中)、npm 的 `_npx` 缓存、版本管理器的 `lib/node_modules` (用户全局包清单的唯一所在)、pnpm / yarn 的 store。删后无法由项目级重装恢复, ADR 0002 的「可恢复, 非数据损失」前提在此不成立 |
| 编辑器 / IDE          | `.vscode` `.vscode-insiders` `.vscode-server` `.cursor` `.antigravity`        | 扩展目录逐个自带 `node_modules`, 属应用自身而非用户项目, 重装扩展才能还原                                                                                                                                                                                                                 |
| 系统 / 应用数据根     | `Library` `.local` `.config` `.cache` `.claude`                               | macOS 的 `Library` 与 XDG 根下散落应用私有安装树 (macOS 的 fnm、各类应用的插件目录); 本机实测命中 `Library/Application Support/Kap/plugins` 与 `.config/opencode`                                                                                                                         |

- **语义与用户名单完全一致** (任意一级目录名命中即跳过), 只是默认值不再为空; 名单项依平台与用户环境而异 (Linux 上没有 `Library`), 故**零命中不告警**: 与手写名字拼错不同, 后者是可修正的输入错误 (见 [行为契约](../protocol/behavior-contract.md) BC-09);
- **用户可覆盖**: 配置文件显式写出 `exclude` (含写空数组) 即以用户名单为准, 默认名单不参与; 想「默认之外再加」就在名单里带上要保留的默认项。覆盖不会造成漏放: 删除面另有一道不受用户配置影响的「语义闸」(疑似安装树默认不进删除批, 见 [删除安全闸](deletion-guard.md));
- **保守取向**: 宁可挡住个别同名的真实项目 (用户可自行从配置中删除该项), 也不漏放安装树; 词表是保守基线而非完备清单: 未收录的应用私有根 (如某工具在 home 下的专属目录) 由用户按需补进 `exclude`。

## 配置初始化模型

- **首次运行且无配置**: TTY 下自动进入初始化向导; 非 TTY 静默回退「以当前工作目录为根」并明确提示 (含 `sweep-nm init` 指引), 不询问 (防卡死脚本与将来的定时任务)。
- **`sweep-nm init`**: 显式重进向导, 重写配置; 非 TTY 下报错退出 (不得静默「成功」)。
- **向导内容**: 三问 (扫描根, 默认家目录; 排除名单, 空答取内置默认名单: 显式写出的 `exclude` 会接管默认值, 回填空数组等于「一路回车把默认保护写没了」, 与默认值本身相悖; 包含名单, 可留空) → **逐根校验 (存在性与根锚点形态)** (不存在的根、以及落在符号链接路径上的根当场提示并重问, 坏输入挡在落盘前; 后者删除侧必整批拒绝, 见下方「配置规格」的 `roots` 条目, 向导按同一判定提前暴露它) → **回显解析结果并确认** (默认 Y) → **落盘前锚点检查 (写入侧)** (配置路径或其祖先链为符号链接即拒并重问「确认写入?」, 见下条) → 落盘并**回显配置全文** (路径行做家目录缩写后经净化: 与其余外部路径回显同一坐标; 正文与落盘文件内容一致、整体缩进 2, 便于当场核对与复制, 该回显块**刻意不净化**: 它与落盘文件逐字一致是供对照复制的承诺, 净化会破坏该承诺, 界线见 [行为契约](../protocol/behavior-contract.md) OF-14 的排除项); 解析支持 `~` / `~\` 展开与成对引号内的空格保留, 未配对引号按普通字符处理。
- **向导形态**: 顶栏 `▍ SWEEP-NM  初始化向导` + 中性块说明行 (`░` 前缀 + 压暗) + 压暗的提示段 (`[默认: …]` / `[回车采用默认名单 (N 条)]` / `[回车跳过]` / `(Y/n)`); 「回显解析结果」由 JSON 形态改人话 `将写入 N 个扫描根 · 排除 M 条 · 包含 K 条` (N / M / K 由解析结果实时计数), 落盘 JSON 全文的回显仍在其后保留 (内容与文件一致、整体缩进 2); 校验失败行走行首红色 `✗`、落盘成功行把绿色 `✓` 置于行尾。完整规格 (含向导顶栏的字段取舍与 TTY 专属边界) 见 [命令面与输出](../../packages/sweep-node-modules-cli/docs/designs/cli-surface.md)「输出规格 · `init` 向导」。
- **向导写入轮强制预览**: 本轮刚生成配置时, **即使带 `--yes` 也只预览** (stderr 说明), 复核清单后方可再次运行执行; 「看清再删」在首次使用路径上同样成立。
- **覆盖保护**: 配置已存在时先确认是否覆盖 (`配置已存在 (<path>), 是否覆盖? (y/N)`, 提示段压暗), 默认否; 中途取消统一输出「已取消, 未写入配置」, 不落盘; 取消 / 拒绝分支不加色块前缀 (中性终态, 加色块会附上「成功 / 失败」的误导语义)。
- **落盘前锚点检查 (写入侧)**: 确认写入后、任何写动作 (含建目标目录) 之前, 配置路径 (旗标 / 环境变量 / 平台默认给的拼写) 及其祖先链逐级 lstat; 任一级为符号链接 (含悬空链接) 即以红色 `✗` 给出链接定位与配置拼写、并重问「确认写入?」(与逐根校验同形), 路径修好前不写一个字节。配置路径为悬空链接时, 覆盖判重 (`lstat` 语义, 不跟进末段) 同样算「已存在」, 故这类路径会先出覆盖一问, 随后才在写入面被拒。理由: 写入会跟随符号链接, 被完整改写的是链接目标 (任意可写文件) 而非配置位置, 而回执报的仍是用户给的拼写, 事后看不出实际写到哪。判定与删除侧的根锚点同一实现 (`guard.ts` 的 `firstSymlinkOnTarget`, 见 [行为契约](../protocol/behavior-contract.md) BC-40), 系统固有链接 (macOS 的 `/tmp`、`/var`) 同样命中, 改写为不含符号链接的形态即放行: 与下方「配置规格」`roots` 条目的真实路径形态要求同源。
- 实现边界与决策见 [ADR 0004](../../packages/sweep-node-modules/docs/adrs/0004-config-initialization-wizard.md)。

## 错误与边界

| 场景                                           | 处置                                                         |
| ---------------------------------------------- | ------------------------------------------------------------ |
| 显式来源 (旗标 / 环境变量) 指向不存在的文件    | 硬报错 `配置不存在 (<path>)` + 退出码 1 (不得静默回退扫 cwd) |
| 平台默认来源缺失                               | 软行为: 向导 (TTY) 或 cwd 回退 (非 TTY)                      |
| 配置损坏 (JSON 解析失败 / 空文件 / 字段类型错) | 逐字段具体报错 (含路径与病因) + 退出码 1                     |

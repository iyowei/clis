# 集合仓定位 (Collection Positioning)

> 文档类型: 仓库级设计
> 适用对象: 本仓维护者与 AI Agent
> 状态: 重定位进行中 (仓库新名 `iyowei/clis` 已定; 改名与组织落地见[重定位执行与验证](collection-relocation.md))

## 定位

本仓是 **iyowei 的 CLI 工具集合仓**。边界就一句话:

> 我自己日常开发用的 CLI 工具及其脚手架; 主要用途就是开发 CLI, 用 monorepo 方式管理; 能让不同 CLI 复用的包也抽离出来, 同样在这个仓库的 `packages/` 下维护。

三层身份同仓并存:

1. **工具宿主**: 每个 CLI 工具及其配套包都属于这个集合 (现为 `sweep-node-modules` 一族);
2. **复用库的家**: 跨工具共享的库抽成独立包, 与工具在同一个仓库里演进 (分类与发布策略见[包分类与发布协议](package-classification.md));
3. **脚手架本体**: 本仓的工程骨架就是新项目的模板, 生成器从骨架快照产出独立的新集合仓 (见[生成器包](scaffold-package.md)与[模板快照机制](scaffold-template-snapshot.md))。

## 单源与生成物

本仓是工程骨架的**唯一事实源**。脚手架不维护第二份模板: 模板是「本仓骨架的泛化快照」, 由生成器包的构建步骤产出。仓库改了, 模板就跟着改, 不需要人工同步。

## 命名

- 仓库: `iyowei/clis`;
- 包 scope: `@iyowei/*` (工具与库一律入 scope);
- 生成器包: 发布时不用 scope (原因与解除条件见[技术债登记](tech-debt.md))。

## 成功标准

- 新 CLI 项目一条指令就能生成, 生成物当场通过全部工程闸门;
- 现有包 (sweep-node-modules 两包) 的发布链闭环零回退 (验证清单见[重定位执行与验证](collection-relocation.md));
- 集合新增包有章可循: 分类、依赖方向、发布开关、工程要求都有明文规定 (见[包分类与发布协议](package-classification.md)与[依赖方向纪律](dependency-direction.md))。

## 明确不做

- 不做面向公众的通用脚手架产品 (只给本仓自己的开发用);
- 不接受与本边界无关的项目进仓;
- 不做「多份模板的人工同步机制」(模板是生成物, 不是需要维护的副本)。

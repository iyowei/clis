# 模板快照机制 (Template Snapshot)

> 文档类型: 仓库级设计
> 适用对象: 本仓维护者与 AI Agent
> 前置: [生成器包](scaffold-package.md)

## 一句话说清

模板**不是**需要维护的副本, 而是本仓骨架的**泛化快照**: 由生成器包的构建步骤直接从本仓产出。仓库改了, 模板就跟着改, 不需要人工同步。

## 骨架清单 (快照取哪些文件)

快照**只取清单里列出的文件**, 不整个仓库照搬。清单里的文件分四类处置:

| 类       | 内容                                                                                                                                                                                                                                         | 处置                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 直接快照 | 配置文件 (oxlint / prettier / editorconfig / gitattributes / gitignorerc / nvmrc / npmrc / bunfig / turbo / tsconfig) / workflows / 通用脚本 (ci / install-git-hooks / safe-install / 闸门族) / docs 骨架 / CONTRIBUTING、SECURITY、行为准则 | 原样进模板                                                                                     |
| 泛化替换 | 含项目名的骨架文件 (实测 15 个, 集中在: make-mutants / tsconfig / run-conformance / issue 模板 / package.json / 各 workflow 命令)                                                                                                            | 按词汇表替换后进模板                                                                           |
| 重置     | 根 README / 包 README / CHANGELOG / docs 领域内容 / 包源码                                                                                                                                                                                   | 换成模板化骨架 (空文档 / 最小示例包; docs 骨架按[文档分层协议](docs-layering.md)生成) 再进模板 |
| 排除     | 领域内容: 现有包的 src 与测试、conformance 语料与契约条款、safety-guardrails 等领域文档、历史 ADR                                                                                                                                            | 不进模板 (增强档的**机制**文件保留, **内容**由新项目自填)                                      |

这份清单是这套机制唯一需要登记的地方: 本仓新增骨架文件时, 判断它的分类, 往清单加一行就行。

## 泛化词汇表

| 变量        | 含义                             | 出现位置 (全部替换)                 |
| ----------- | -------------------------------- | ----------------------------------- |
| `{name}`    | 项目名 (如 `sweep-node-modules`) | 包名 / 目录名 / 文档标题            |
| `{scope}`   | npm scope (如 `@iyowei`)         | 包名前缀                            |
| `{binName}` | 主 bin 名 (如 `sweep-nm`)        | bin 字段 / 启动器 / 帮助页          |
| `{owner}`   | 仓库所有者                       | LICENSE / package.json author       |
| `{repoUrl}` | 仓库地址                         | repository / homepage / bugs / 徽章 |

## 构建自检 (构建即闸门)

快照产出后, 构建步骤必须检查:

1. 清单内每个文件都成功产出;
2. 泛化后模板内**不再出现原项目词汇** (原包名 / 原 bin 名 / 原 owner): 任何残留即构建失败。有了这条, 模板泄漏不用再靠人工评审兜底, 构建时就会被拦住。

## 生成器怎么用模板

生成器 (详见[生成器契约](scaffold-contract.md)) 以 `assets/template/` 为唯一输入, 按档裁剪 (见[能力分档](capability-tiers.md)) 并代入用户变量, 产出新项目。

# 模板快照机制 (Template Snapshot)

> 文档类型: 仓库级设计
> 适用对象: 本仓维护者与 AI Agent
> 前置: [生成器包](scaffold-package.md)

## 机制一句话

模板**不是**需要维护的副本, 而是本仓骨架的**泛化快照**: 由生成器包的构建步骤从本仓工作树实时产出。仓库骨架演化即模板演化, 不存在同步动作。

## 骨架清单 (快照的输入面)

快照按**显式清单**取文件, 不整仓复制。清单分四类处置:

| 类       | 内容                                                                                                                                                                                                                                       | 处置                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- |
| 直接快照 | 配置件 (oxlint / prettier / editorconfig / gitattributes / gitignorerc / nvmrc / npmrc / bunfig / turbo / tsconfig) / workflows / 通用脚本 (ci / install-git-hooks / safe-install / 闸门族) / docs 骨架 / CONTRIBUTING、SECURITY、行为准则 | 原样进模板                                                  |
| 泛化替换 | 含项目名的骨架文件 (实测 15 个, 热点: make-mutants / tsconfig / run-conformance / issue 模板 / package.json / 各 workflow 命令)                                                                                                            | 按词汇表替换后进模板                                        |
| 重置     | 根 README / 包 README / CHANGELOG / docs 领域内容 / 包源码                                                                                                                                                                                 | 换模板化骨架 (空文档 / 最小示例包) 后进模板                 |
| 排除     | 领域内容: 现有包的 src 与测试、conformance 语料与契约条款、safety-guardrails 等领域文档、历史 ADR                                                                                                                                          | 不进模板 (强装置档的**机制**文件保留, **内容**由新项目自填) |

清单是本机制的唯一登记点: 本仓新增骨架文件时, 只需判断其类属并往清单加一行。

## 泛化词汇表

| 变量        | 含义                             | 出现形态 (全部替换)                 |
| ----------- | -------------------------------- | ----------------------------------- |
| `{name}`    | 项目名 (如 `sweep-node-modules`) | 包名 / 目录名 / 文档标题            |
| `{scope}`   | npm scope (如 `@iyowei`)         | 包名前缀                            |
| `{binName}` | 主 bin 名 (如 `sweep-nm`)        | bin 字段 / 启动器 / 帮助页          |
| `{owner}`   | 仓库主                           | LICENSE / package.json author       |
| `{repoUrl}` | 仓库地址                         | repository / homepage / bugs / 徽章 |

## 构建自检 (构建即闸门)

快照产出后, 构建步骤必须断言:

1. 清单内每个文件都成功产出;
2. 泛化后模板内**不再出现原项目词汇** (原包名 / 原 bin 名 / 原 owner): 任何残留即构建失败。这条把「模板泄漏」从人工评审变成物理不可达。

## 生成器消费

生成器 ([契约见下篇](scaffold-contract.md)) 以 `assets/template/` 为唯一输入, 按档裁剪 (见[装置分档](capability-tiers.md)) + 代入用户变量, 产出新项目。
